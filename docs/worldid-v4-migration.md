# World ID 4.0 Migration Guide

> Source: https://docs.world.org — fetch https://docs.world.org/llms.txt for the full index.

## Overview

World ID 4.0 introduces two proof types:

- **Uniqueness proofs** — one-time checks (same as v3 nullifiers, but one-time-use only)
- **Session proofs** — new in 4.0; stable `session_id` links the same user across requests

| Proof type       | v3 behavior                      | v4 behavior                                                       | Store in backend     |
|------------------|----------------------------------|-------------------------------------------------------------------|----------------------|
| Uniqueness proof | Nullifier prevented proof reuse  | Nullifier still prevents reuse and is one-time-use                | Used nullifiers      |
| Session proof    | N/A — nullifiers were persistent | `session_id` = stable link. `session_nullifier` = per-proof replay guard | `session_id`    |

---

## IDKit 4.x Breaking Changes

1. **`rp_context` is required** — requests need `rp_id`, `nonce`, `created_at`, `expires_at`, `signature`
2. **Response shape changed** — no need to reshape payload or compute `signal_hash`
3. **Verify endpoint changed** — `POST https://developer.world.org/api/v4/verify/{rp_id}` (not `/api/v1/verify/{app_id}`)
4. **`@worldcoin/idkit-standalone` discontinued** — use `@worldcoin/idkit-core` for vanilla JS

---

## Migration Timeline

| Phase | Dates | What happens |
|-------|-------|--------------|
| Phase 1 — Migration | Now → June 1, 2026 | Upgrade SDKs/contracts, register RP, create v4 actions. New users get both v3 and v4 credentials |
| Phase 2 — Transition | June 1, 2026 → March 31, 2027 | New users can only create 4.0 proofs. All users migrate to v4 |
| Phase 3 — v3 Cut-off | April 1, 2027 onward | v3 proofs no longer generated by World App |

## Migration Paths

### 1. One-Time / Long-Running Actions

Apps with a single long-running action (e.g., "one stamp per human ever").

**Key: use `allow_legacy_proofs: true` during Phase 2, switch to `false` at cut-off date.**

Steps:
1. Upgrade SDKs and API calls
2. Register in Developer Portal (get `rp_id` and `signing_key`)
3. Set a **Transition Date (TD)**: start accepting v4 proofs with `genesis_issued_at = TD` and `allow_legacy_proofs: true`
4. At a future **Cut-off Date (CD > TD)**: set `allow_legacy_proofs: false`

Contract pattern — check BOTH old and new nullifiers:
```solidity
// New contract mint (v4 proof)
function mint({ nullifier }) {
  if (OldContract.hasMinted[msg.sender] || hasMinted[msg.sender]) revert AlreadyMinted();
  if (OldContract.oldNullifierHashes[nullifier] || nullifierHashes[nullifier]) revert DuplicateNullifier(nullifier);
  Verifier.verify(...);
}

// Legacy support during migration (v3 proof)
function mintLegacy({ nullifierHash }) {
  if (OldContract.hasMinted[msg.sender] || hasMinted[msg.sender]) revert AlreadyMinted();
  if (OldContract.oldNullifierHashes[nullifierHash] || nullifierHashes[nullifierHash]) revert DuplicateNullifier(nullifierHash);
  WorldIDRouter.verify(...);
}
```

### 2. Short-Term Recurring Actions

Apps with multiple short-lived actions (e.g., daily voting).

**Key: pick a future action name to start v4-only. No need for legacy support.**

- Upgrade SDK and portal account
- For new actions after TD: use `allow_legacy_proofs: false`

### 3. Recurring Verifications / Credential Checks

Apps that verify users repeatedly with the same action.

**Key: migrate to Session Proofs. `session_id` replaces nullifier as stable identifier.**

Creating a session:
```js
const rpContext = await fetch("/api/worldid/rp-context").then(r => r.json());

const request = await IDKit.createSession({
  app_id: APP_ID,
  rp_context: rpContext,
}).constraints(any(CredentialRequest("orb")));

const completion = await request.pollUntilCompletion({ timeout: 120000 });
// Save this — it's the stable user identifier across sessions
const sessionId = completion.result.session_id;
```

Proving a subsequent session:
```js
const request = await IDKit.proveSession(sessionId, {
  app_id: APP_ID,
  rp_context: rpContext,
}).constraints(any(CredentialRequest("orb")));

const completion = await request.pollUntilCompletion({ timeout: 120000 });
```

## `inclusion_proof_failed` — What It Means

This error from MiniKit/IDKit means the user's identity commitment **is not in the Merkle tree** for the requested credential level. Common causes:

1. **v3-only credential + v4 app** — after enabling World ID 4.0 in the portal, the app checks the v4 Merkle tree. A user who has not yet upgraded their World App credential to v4 will fail. Fix: set `allow_legacy_proofs: true` to check the v3 tree as well.
2. **Device level requested but user only has Orb** — or vice versa.
3. **Testnet vs mainnet mismatch** — staging apps must use staging credentials.

---

## Key Notes

- `genesis_issued_at` = when the user originally got their credential (e.g., went to an Orb), NOT when they upgraded to v4.
- A user Orb-verified in 2023 who upgrades to v4 in 2025 still has `genesis_issued_at` from 2023.
- Users with pre-v4 credentials MAY receive a new credential based on issuer policy; `genesis_issued_at` still reflects original issuance.
- Phase 2 should be at least one year long — users with old credentials won't be able to claim after Phase 3.
